Performance turns an agent's call history into a board of cards that help you understand traffic, results, and recurring patterns.

<Note>
  Performance reports on the agent's real phone traffic. Web calls are excluded from every card, drilldown, and filter, and **Call type** does not offer that value.
</Note>

Open **Performance** and choose an agent. The page is a single board: every chart, table, and big number on it is a card you can arrange, retype, and drill into.

<Note>
  Data Tables and Proactive Monitoring are no longer separate tabs. Existing data tables are converted to cards the first time you open the page, and a one-time note tells you which view received them. Proactive Monitoring opens in a side panel from the account menu or a report link.
</Note>

## Filter the calls

The date range and filters in the header apply to every card in the active view. Available filters can include outcomes, topics, end reasons, call status, call type, sentiment, phone numbers, call duration, day of week, and time of day. For outbound campaigns you can also filter and group by the campaign's outbound variables, and for inbound agents by each Webhook block's status and payload fields, alongside API block fields.

Filters you set appear as chips in the header. Remove a chip to clear that filter. Filter choices are limited to values available for the selected agent and date range.

## Read the cards

**Add widget** offers preset cards for common questions:

| Card | What it shows |
| --- | --- |
| **Calls over time** | Call volume across the selected range |
| **Total calls** | A single number for the range |
| **Average call length** | Mean call duration |
| **Calls by outcome** | Calls grouped by the outcome recorded by the flow |
| **Outcome detail** | Outcomes with supporting metrics in a table |
| **Unique customers** | The number of distinct customers, deduplicated by phone number |

<Note>
  A unique count deduplicates by customer phone number and does not add up, so totals, shares, pie charts, and stacking are withheld for it. On a time axis, every bucket shows the whole range's unique count, and the card notes this.
</Note>

Select a segment, point, or row to open the matching calls. This lets you move from an aggregate pattern to the conversations behind it.

Each card shows when its data was last updated. Hover a number to see the count or share behind it.

### Change how a card looks

Open a card's **More options** menu to switch between compatible chart types, such as **Time series**, **Bar chart**, **Big number**, **Top list**, **Table**, **Pie**, or **Sankey**. Only the types that suit the card's question are offered — a pie cannot show a time grouping, for example.

Switching the type changes the presentation only. It never changes the number a card computes.

### Arrange the board

- Drag a card to reorder it.
- Drag a card's edge or corner to resize it.
- Select **Edit in Explore** (the pencil) to change the question behind a card.
- Use **More options** to export the card's data or remove it from the view.

Layout changes belong to the active view. If a board cannot be saved, the header shows a **Not saved** warning; select it to retry.

## Build your own card

Select **Add widget** to add a preset card, or **Build a query** to open **Explore**.

Explore replaces the board while you work in it. Build a question by choosing what to count, how to group it, and which calls to include:

| Part | Purpose |
| --- | --- |
| **Entity and measure** | What each number counts, such as calls or a saved metric |
| **Group by** | What each series, slice, or row represents |
| **Filters** | Which calls contribute to the result |

Save the result to add it to the board. Use the browser's Back button or the back arrow to leave Explore; if you have unsaved work, Phonely asks before discarding it.

You can save a metric or filter to reuse it across cards, and manage those saved definitions from Explore.

## Work with views

A view keeps a board's cards, filters, and settings for an agent. Use the view selector to switch between them and its menu to create, rename, duplicate, reorder, or delete a view.

Use separate views for questions that need different scopes, such as weekly operations, negative-sentiment calls, or a specific outcome. Give each view a name that describes the question it answers.

## Interpret the results

- Use **outcomes** to measure results recorded by flows or updated after a call.
- Use **topics** to understand what callers discussed.
- Use **end reasons** to understand how calls stopped.
- Open the underlying calls before treating a change on a card as a product or flow issue.

<Tip>
  Keep the date range and filters consistent when comparing results. A change in scope can look like a change in agent performance.
</Tip>
