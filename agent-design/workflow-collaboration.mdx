Workflow collaboration helps you work safely on a flow when other teammates are also making changes. Instead of overwriting updates silently, Phonely notifies you when a newer remote version is available and gives you tools to compare your current draft with the incoming changes before deciding what to do next.

Use this when:

- More than one person is editing the same workflow
- You have local edits open and a teammate saves a newer version
- You want to review exactly what changed before loading the latest version

This is especially useful for prompt-heavy flows, routing changes, and shared agents where multiple people may be updating the same nodes.

## How Workflow Collaboration works

When Phonely detects that a teammate has made newer changes to the same flow, a collaboration banner appears at the top of the Flow Editor.

The banner shows that:

- New remote updates are available
- Who made the remote update
- Actions you can take next

## Collaboration banner

When remote updates are detected, Phonely displays a banner across the top of the workflow canvas.

<Frame>
  ![Collaborationbanner](/assets/collaborationbanner.png)
</Frame>

The banner includes:

#### New remote updates available by \[teammate\]

This lets you know that another teammate has made a newer version of the current flow.

#### Review Changes

Opens the comparison view so you can inspect the differences between your local version and the incoming remote version.

#### Apply Latest

Loads the newest remote version into your editor. Use this when you do not need to keep your current local draft and simply want to move to the latest version.

#### Save Local & Load Latest

Saves your current local work, then loads the incoming remote version. Use this when you want to preserve your current draft before switching to the latest shared version.

## Review Flow Changes

Click **Review Changes** from the collaboration banner to open the **Review Flow Changes** modal. This is where you compare your current local draft with the incoming remote version side by side.

At the top of the modal, Phonely shows:

- **Local Draft** — your current local draft
- **Remote Updates** — the incoming remote version

You will also see a change count such as:

- **1 change detected**

This gives you a quick summary of how many changed areas were found.

## What the comparison modal shows

The comparison modal is designed to help you understand exactly what changed before you apply anything.

It includes:

- a side-by-side comparison layout
- a list of modified nodes
- the number of changed fields in each node
- a **Simple** mode
- an **Advanced** mode
- expandable text differences
- clear color-coded comparison between local and remote content

## Local Draft and Remote Updates

At the top of the modal, the comparison is split into two sides:

### Local Draft

This is your current local version of the flow — the draft open in your editor.

### Remote Updates

This is the newer version saved remotely by your teammate.

This layout makes it easy to compare your current work with the incoming version before taking action.

## Modified Nodes

Below the headers, Phonely lists the nodes that changed under **Modified Nodes**.

Each changed node appears by name, for example:

- **Branch selection**

Phonely may also show an internal node identifier such as:

- **PROMPT\_4366832**

This helps you identify exactly which part of the workflow was modified.

If more than one node changed, each one appears in this section.

## Changed field count

Each modified node includes a badge showing how many fields changed, for example:

- **1 fields**

This tells you how many individual configuration fields inside that node differ between the local and remote versions.

You can expand the node to inspect those differences.

# Simple mode

By default, the comparison view can be shown in **Simple** mode.

Simple mode is described in the modal as:

> **quick non-technical summary**

This view is designed for readability. It is best when you want to understand prompt or content changes without reading raw structured data.

## What Simple mode shows

In Simple mode, changed content is displayed side by side in a more human-readable format.

For example, if a prompt node changed, you may see readable content such as:

- **Objective**
- **Steps**
- **Guidelines**

The left side shows the local content and the right side shows the incoming remote content.

This makes it easy to compare edits such as:

- added or removed wording
- revised instructions
- prompt clarifications
- small text changes inside an existing node

In the screenshots you shared, the changed node was **Branch selection**, and the difference was shown inside the `data.frontend.prompt.value` field as readable prompt text.

## Color-coded comparison in Simple mode

Simple mode uses side-by-side color treatment to show what changed.

In the example shown:

- the local version appears in one color
- the incoming remote version appears in another color

This helps you quickly spot which wording belongs to your current draft and which wording belongs to the remote update.

## Show more / Show less

When a changed field contains long content, Phonely may initially show a shortened preview.

Use:

- **Show more** to expand the full content
- **Show less** to collapse it again

This is especially useful for long prompts, multi-step instructions, or nodes with detailed guidelines.

In the example shown, the prompt initially appeared in a shorter preview, and **Show more** expanded the full comparison.

# Advanced mode

If you need a more technical comparison, switch the modal to **Advanced** mode using the toggle in the top-right area of the comparison view.

Advanced mode is described as:

> **Git-style JSON line diff**

This mode is useful when you want to inspect the exact structured data that changed.

## What Advanced mode shows

In Advanced mode, the changed node is displayed as a side-by-side structured diff.

This includes fields such as:

- `name`
- `instructions`
- `prompt`
- `exitconditions`
- `variables`

Changed lines are highlighted in a Git-style diff layout so you can see the precise field-level difference.

In the screenshots you shared, the changed value was inside:

- `prompt.value`

The local side showed the earlier text, and the remote side showed the updated version with the changed wording.

---

## When to use Advanced mode

Use **Advanced** mode when:

- you want exact field-level differences
- you are reviewing configuration-heavy changes
- you need to verify raw node data
- you are comfortable reading structured diff output
- the change is too subtle to rely only on the readable summary

Use **Simple** mode when you want a faster, easier review of content changes.

# Actions you can take after reviewing

After inspecting the differences, return to the collaboration banner and choose the next step.

## Apply Latest

Use **Apply Latest** when you want to load the remote version directly.

Choose this when:

- the remote update is the version you want to continue with
- you do not need to preserve your current local draft separately
- you have already reviewed the changes and are ready to switch

This updates your editor to the newest shared version.

---

## Save Local & Load Latest

Use **Save Local & Load Latest** when you want to keep your current local work before switching to the remote version.

Choose this when:

- you have local edits you do not want to lose
- you want to preserve your draft before loading the newest shared version
- you want to compare or reuse your local work later

This is the safer choice when you have already made meaningful changes in your editor.

---

## Review Changes again before deciding

If you are unsure which version to keep, use **Review Changes** first.

This is especially important when:

- the changed node affects prompt instructions
- more than one contributor is editing the same flow
- the latest update may affect logic, routing, or behavior

---

# A typical collaboration workflow

A common workflow looks like this:

1. You open a shared workflow and start editing.
2. Another teammate makes changes to the same flow.
3. Phonely detects the new remote version.
4. A collaboration banner appears at the top of the editor.
5. You click **Review Changes**.
6. The **Review Flow Changes** modal opens.
7. You compare:
   - **Local Draft**
   - **Remote Updates**
8. You inspect the changed node under **Modified Nodes**.
9. You review the differences in **Simple** mode.
10. If needed, you switch to **Advanced** mode for a structured diff.
11. After reviewing, you choose:

- **Apply Latest**, or
- **Save Local & Load Latest**

This prevents accidental overwrites and makes shared editing much safer.
